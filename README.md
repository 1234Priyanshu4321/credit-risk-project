# Credit risk prediction API

Predicts whether a loan applicant is high or low risk using the German Credit dataset (1000 applicants, 20 features). Returns a prediction, a probability score, and SHAP-based feature explanations for each request.

Live API: https://credit-risk-project-243y.onrender.com

---

## What it does

Send a POST request with an applicant's details — checking account status, loan duration, credit history, purpose, savings, employment, etc. — and the API returns:

- `prediction`: 0 (low risk) or 1 (high risk)
- `probability_high_risk`: the model's confidence
- `top_features`: which features pushed the prediction in which direction (SHAP values)

The explainability endpoint (`/predict/explain`) is the interesting part. Most credit risk models are black boxes. This one tells you *why* it flagged someone — for example, that a no-balance checking account (`Status_A11`) was the biggest driver, more than loan duration or amount.

---

## Endpoints

```
GET  /health            — model status and CV scores
POST /predict           — prediction + probability
POST /predict/explain   — prediction + probability + SHAP feature contributions
```

Try them at `/docs` (Swagger UI).

---

## How the model works

Three models are trained and compared via 5-fold stratified cross-validation:

- Logistic Regression
- Random Forest
- XGBoost

The one with the highest mean ROC-AUC across folds is selected automatically. On the current dataset, Random Forest wins with a CV mean ROC-AUC of 0.79 and a held-out test ROC-AUC of 0.80.

Each model is a `sklearn` Pipeline: a `ColumnTransformer` (StandardScaler for numeric features, OneHotEncoder for categorical) followed by the classifier. This means the pipeline handles raw input directly — no manual encoding needed at inference time, and unknown category values are handled gracefully instead of crashing.

## Running locally

```bash
git clone <repo>
cd credit-risk-project

pip install -r requirements.txt

# Train the model (saves artifacts/ folder)
python train.py

# Start the API
uvicorn app.main:app --reload
```

Open http://localhost:8000/docs to test interactively.

`train.py` needs `german.data` in the same directory (included in the repo). It takes about 60-90 seconds to run CV across all three models.

## Project structure

```
credit_risk_model.ipynb   — EDA, model comparison, SHAP summary plots
train.py                  — training script, saves artifacts/
german.data               — raw dataset (UCI German Credit)
requirements.txt

app/
  main.py                 — FastAPI app and routes
  model.py                — loads pipeline at startup, predict/explain logic
  schema.py               — Pydantic input schema with all valid categorical values

artifacts/                — generated by train.py, not committed
  model.joblib            — fitted pipeline (preprocessor + classifier)
  metadata.joblib         — CV scores, model name, test AUC
  metadata.json           — same as above, human-readable
```

## Input format

All 20 features from the German Credit dataset. Categorical fields use letter codes from the original dataset spec.

Example request body:

```json
{
  "Status": "A11",
  "Duration": 24,
  "CreditHistory": "A32",
  "Purpose": "A43",
  "CreditAmount": 4000,
  "Savings": "A61",
  "EmploymentDuration": "A73",
  "InstallmentRate": 2,
  "PersonalStatusSex": "A93",
  "OtherDebtors": "A101",
  "ResidenceDuration": 2,
  "Property": "A121",
  "Age": 35,
  "OtherInstallmentPlans": "A143",
  "Housing": "A152",
  "ExistingCredits": 1,
  "Job": "A173",
  "NumberOfDependents": 1,
  "Telephone": "A191",
  "ForeignWorker": "A201"
}
```

Valid values for each categorical field are documented in `app/schema.py` with descriptions (e.g. `A11` = checking account balance < 0 DM, `A14` = no checking account). The `/docs` page shows these inline.

---

## Dataset

UCI German Credit dataset. 1000 rows, 20 features (7 numeric, 13 categorical), binary target (1 = good credit / 0 = bad credit, remapped to 0/1 risk labels in `train.py`).

Source: https://archive.ics.uci.edu/ml/datasets/statlog+(german+credit+data)

## Notes

- The free Render instance spins down after 15 minutes of inactivity. First request after idle takes ~30-50 seconds.
- SHAP feature names have `num__` and `cat__` prefixes from the ColumnTransformer (e.g. `cat__Status_A11`, `num__Duration`). These map directly to the input field names.
- If Random Forest is selected, SHAP uses `TreeExplainer`. If Logistic Regression wins, it uses `LinearExplainer`. The branching is in `app/model.py`.
